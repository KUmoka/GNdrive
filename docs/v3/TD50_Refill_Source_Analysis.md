# TD50%における粒子補充：現行コードの仕様抽出

調査日: 2026-10-04。対象: GNdrive/GNSystems.cs の現行作業ツリー。実装変更・ビルド・実機試験は行っていない。

## 対象条件
UsesTDBlanket = Definition.Generation && Definition.TDBlanket && Definition.TD。
TD比率 f はパーツのTopologicalDefects量 / 容量を0～1に制限した値。通常のEC駆動生成炉には下記50%制限は適用されない。
生成能力とGeneration要求が必要。TD Blanket対象でf=0なら生成率0。生成率上限はParticleGenerationRate × Syncで、Trans-AM倍率はこの上限に直接掛からない。
GenerationとBlanketは状態整合・操作時に連動する。

## 生成量の決定（Step、879～917行付近）
1ステップの粒子需要をD、貯蔵量をP、空き容量をF、生成上限をR×dtとする。
通常の生成目標は D+F。
ただしBlanket有効かつf<=0.5なら、目標を max(0,D-(SafeGuard ? 0 : P)) に差し替える。
つまりTD50%を含む領域では貯蔵補充のための需要Fを除去する。待機中D=0では生成しない。
SafeGuard OFFでは貯蔵分を優先して見込み需要から差し引く。ONでは貯蔵を使用せず、現在の需要分だけ生成する。

## 電力と質量エネルギー
粒子数q、ECPerParticle=cなら生成消費電力はq*c。
Blanket要求発電量はq*c*2*fで、バリオン資源の質量エネルギー変換から供給する。TDそのものが独立して発電する仕組みではない。
0<f<0.5: 不足電力q*c*(1-2*f)を船のECで補助。アクセス可能ECで事前に生成量を制限。
f=0.5: 発電=生成消費でEC収支0。これは電力条件であり、タンク補充禁止は別の明示的なコード条件。
f>0.5: 粒子需要+空き容量を生成目標にできる。ECに空きがあれば、余剰電力で充電するためさらに生成量を増やせる。生成上限・EC空きで制限し、余分な粒子はspillとして処理。
バリオン不足時は実供給に合わせて生成を縮小し、Blanket/GenerationをOFF、BlanketStarvedを設定する。

## 粒子決済（974～997行付近）
生成粒子と許可された貯蔵粒子を効果に配分。実消費後の余剰はタンクへPutし、受け入れ不能分はspill。
50%以下でも実効果が計画より縮小した場合等には決済余剰が入り得る。正確な仕様は「補充目的の生成をしない」であり「絶対にタンクへ入らない」ではない。

## 観測との対応
TD50%、SafeGuard ON、生成能力が現在需要以上、バリオン供給ありなら、生成粒子だけで推進でき、貯蔵は減らず補充もされない。今回の報告と整合するが、ユーザー実機のSafeGuard状態・全搭載モジュールは未確認。
SafeGuard OFFなら、同条件でも原則として貯蔵分を先に消費する。

## 変更候補（未実施）
50%ちょうどで補充を許すなら assistedBlanket の <=0.5 を <0.5 へ変更するのが最小の分岐変更。ただし50%での待機補充・バリオン消費も許可する仕様変更となる。境界付近の浮動小数点とテストを含めて別途対応する。
50%未満でも外部ECを使って補充したい場合は、生成目標制限そのものを再設計する必要がある。

## 検証根拠
現行コードの逐次追跡。既存テスト113が50%電力収支、124/125が待機時非生成、130が貯蔵優先を対象とする（今回未実行）。
